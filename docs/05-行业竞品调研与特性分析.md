| 项目 | 仓库 |
|---|---|
| **eDirStat** | github.com/xangelix/edirstat |
| 语言 | Rust |
| GUI | egui |
| 许可 | MIT |

**核心特性：**
- 工作窃取多线程目录遍历（jwalk + rayon）

- **硬链接感知**：准确区分物理副本和硬链接
- 动态 treemap 可视化 + HSL 扩展名渐变着色

**可借鉴：** 去重管线设计、Arena 内存模型、快照序列化方案

## 三、关键技术方案调研

### 3.1 Windows MFT 直接读取

**背景：** WizTree 能在 3 秒内扫描 1TB NTFS 硬盘，关键在于直接读取 MFT（Master File Table），绕过操作系统文件遍历 API。

**Rust 生态可用库：**

| Crate | 能力 | 备注 |
|---|---|---|
| **ntfs-reader** | MFT 扫描 + USN Journal | `Volume::new("\\\\.\\C:")?` → `Mft::new(volume)?` → 迭代文件，3.8 秒 1000 万条 |
| **usn-journal-rs** | USN Journal + MFT 枚举 | 安全封装 Windows API，解析变更原因 |
| **ntfs-core** | 纯 Rust NTFS 解析，无 unsafe | 从裸分区读取 MFT attribute/index/data runs/LZNT1，可用于取证 |
| **ntfs** (Colin Finck) | 通用 NTFS 读写 | 功能最全，但偏通用 |

**注意事项：**
- 需要管理员权限才能直接读取 MFT
- 只能遍历 NTFS 卷（FAT/exFAT 仍需传统扫描）
- WizTree 策略：NTFS → MFT 直读，非 NTFS → 传统 fallback

### 3.2 七阶段去重引擎（eDirStat）

```
Size Partitioning（按大小分组，丢弃单例）
    → Prefix Hashing（4KB 开头哈希，过滤不同格式）
    → Midpoint Hashing（中心区域哈希，检测相似文件内部差异）
    → Suffix Hashing（末尾 4KB 哈希，尾部元数据差异）
    → Multi-Range Hashing（每 100MB 采样，大文件长距离一致性）
    → Full Cryptographic Hash（BLAKE3 全量哈希，仅对候选者）
    → Real-Time Validation（时间戳校验 + 物理确认）
```

**优势：** 只对大概率重复的文件做全量 hash，90%+ 文件在前 3 阶段即被排除，I/O 量极小。

### 3.3 Arena 树结构（DiskSleuth / eDirStat）

传统树结构：每个节点单独 `Box` 或 `Arc` 分配 → 缓存不友好、遍历慢。

Arena 方案：
```rust
struct FileNode {
    name: String,
    size: u64,
    first_child: Option<NodeIndex>,
    next_sibling: Option<NodeIndex>,
    parent: Option<NodeIndex>,
}

struct FileTree {
    nodes: Vec<FileNode>,  // 连续内存，O(n) 遍历
}
```

**优势：**
- 缓存友好（顺序访问）
- 零分配遍历
- 可序列化为二进制（bytemuck + memmap2）
- 单节点 32-bit index（4 字节）替代指针（8 字节）

### 3.4 扫描→UI 解耦模式

```
Scanner Thread(rayon)
    → crossbeam::channel (进度事件)
    → parking_lot::RwLock<FileTree>
        → UI Thread (egui) 通过 snapshot 读取
```

**关键设计（DiskSleuth）：**
- Scanner 写入 `RwLock` 的 write 端
- UI 读取 `RwLock` 的 read 端（不阻塞扫描）
- 或每 100ms 生成不可变快照（rdirstat 方式），UI 只读快照

### 3.5 可视化方案

| 进度通道 | `crossbeam-channel` | 扫描→UI 无锁解耦 |
| 读写锁 | `parking_lot::RwLock` | 比 std 快 3-5x |
| 序列化 | `serde` + `bincode` / `rkyv` | 快照持久化 |
| mmap | `memmap2` | 零拷贝快照加载 |
| TUI | `ratatui` + `crossterm` | 交互式终端界面 |
| 模糊搜索 | `fuzzy-matcher` | 文件名模糊匹配 |
| MIME 检测 | `tree_magic_mini` | 基于内容的类型识别 |
| HTML 图表 | 内嵌 ECharts CDN | 自包含 HTML 导出 |

### 架构参考：rdirstat 的分层模式

```
treesize-core       ← 扫描引擎 + 共享状态 + 快照（当前已在 domain/application）
    ├── scan.rs     ← 并行扫描（已有 fs_scanner）
    ├── snapshot.rs ← 快照泵（可选）
    └── app.rs      ← 状态管理

treesize-cli        ← CLI 输出 + TUI（已有 cli，可扩展 TUI）
treesize-gui        ← egui 前端（已有 gui）
```

类似 rdirstat 的 core/TUI/GUI 三 crate 拆分，共享 `UiSnapshot` 数据结构，渲染层只读。

## 七、总结

### treesize 的差异化优势

在当前 Rust egui 磁盘分析器生态中，treesize 以 **DDD 4 层架构 + TDD** 为工程基础，已发展为功能最全面的开源磁盘分析工具之一。相比 eDirStat（单体）、DiskSleuth（单体）、rdirstat（3 crate），treesize 的模块化程度最高，且功能覆盖面最广。

### 已实现的「杀手级功能」

1. **MFT 直接读取** — 秒级扫描 NTFS 卷，媲美 WizTree
2. **USN Journal 增量扫描** — 首次全量后只扫描变更部分
3. **7 阶段去重流水线** — 参考 eDirStat 设计，大幅减少大文件 I/O
4. **12 类空间浪费检测** — 开源工具中独一无二，超越 Scour 商业工具
5. **Sunburst 环形图** — 与 Treemap 互补的可视化视角
6. **扫描历史趋势** — SQLite 持久化 + 折线图 + 分类/目录增长分析

### 下一步「低挂果实」

1. **扫描快照持久化** — serde 序列化 FileNode 树为二进制文件，支持离线分析
2. **HTML 报告导出** — 内嵌 ECharts treemap，自包含 HTML
3. **交互式 TUI 模式** — ratatui 实现 ncdu 级体验，SSH 远程分析

### 最值得的「长期投入」

1. **Icicle/Flame Graph 视图** — 水平 stacked bars，优于 sunburst 的角度编码偏差
2. **文件拖拽收集删除** — 直观的清理交互
3. **开发者缓存清理** — 18+ 生态系统，差异化功能
