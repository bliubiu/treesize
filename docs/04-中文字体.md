# 04 - 中文字体内嵌

## 1. 概述

treesize GUI 模式依赖中文字体显示界面文本。为确保在所有环境（包括无中文字体的 Linux/macOS 系统、Docker 容器等）中正确显示中文，项目支持将开源中文字体内嵌到可执行文件中。

## 2. 字体选择

### 2.1 推荐字体

| 字体 | 协议 | 说明 |
|------|------|------|
| Noto Sans SC | SIL Open Font License 1.1 | Google 思源黑体，简体中文版 |
| Source Han Sans SC | SIL Open Font License 1.1 | Adobe 思源黑体，与 Noto Sans SC 同源 |

### 2.2 协议说明

Noto Sans SC / Source Han Sans SC 使用 **SIL Open Font License 1.1** 开源协议：
- ✓ 允许自由使用、修改、分发
- ✓ 允许内嵌到软件中（包括商业软件）
- ✓ 允许作为可执行文件的一部分发布
- ✗ 禁止单独出售字体文件

## 3. 安装步骤

### 3.1 下载字体

从 Google Fonts 下载 Noto Sans SC：

```
https://fonts.google.com/noto/specimen/Noto+Sans+SC
```

或从 Adobe 官方仓库下载 Source Han Sans SC：

```
https://github.com/adobe-fonts/source-han-sans/releases
```

推荐下载 **TTF 格式** 的 `NotoSansSC.ttf` 或 **OTF 格式** 的 `SourceHanSansSC-Regular.otf`（简体中文版）。
构建脚本和内嵌代码同时支持 `.ttf` 和 `.otf` 两种扩展名。

> 字体文件检测优先级：
> 1. `assets/NotoSansSC.ttf`（优先，推荐，Google Noto Sans SC TTF）
> 2. `assets/SourceHanSansSC-VF.ttf`（备选，Adobe Source Han Sans SC 可变字体）
> 3. `assets/SourceHanSansCN-Regular.otf`（备选，Adobe Source Han Sans CN OTF）


### 3.2 放置字体文件

将下载的字体文件放入项目 `assets/` 目录，保持原始扩展名。支持同时放置多个字体，构建脚本按优先级检测：

```
treesize/
├── assets/
│   ├── NotoSansSC.ttf             # ← 优先级 1（推荐）
│   ├── SourceHanSansSC-VF.ttf     # ← 优先级 2（可变字体）
│   └── SourceHanSansCN-Regular.otf # ← 优先级 3（OTF 格式）
├── src/
├── build.rs
└── Cargo.toml
```

> 只需放置其中一种格式。构建脚本按上述优先级顺序检测，找到第一个存在的即停止。
> 三种字体文件均可被识别，文件名无需统一为 `NotoSansSC`。

### 3.3 重新编译

```bash
cargo build --release
```

构建脚本会自动检测 `assets/` 目录下的字体文件（按优先级），若存在则设置编译标志 `embedded_font`，GUI 模式将内嵌该字体。编译时终端会输出类似以下提示：

```
warning: treesize@0.1.0: 检测到 assets/NotoSansSC.ttf，将内嵌中文字体
```

## 4. 工作原理

```
build.rs
└── 按优先级依次检测 assets/ 下的字体文件
    ├── 1. assets/NotoSansSC.ttf
    │      → cfg(embedded_font) + cfg(font_ntsc_ttf)
    │      → include_bytes!("../../assets/NotoSansSC.ttf")
    │
    ├── 2. assets/SourceHanSansSC-VF.ttf
    │      → cfg(embedded_font) + cfg(font_shsc_vf_ttf)
    │      → include_bytes!("../../assets/SourceHanSansSC-VF.ttf")
    │
    └── 3. assets/SourceHanSansCN-Regular.otf
           → cfg(embedded_font) + cfg(font_shcn_otf)
           → include_bytes!("../../assets/SourceHanSansCN-Regular.otf")

找到即停止，只有一个字体被嵌入
GUI 编译时按 cfg 标志嵌入对应字体文件
注册为 egui 默认字体族（含中文字符回退）

↓ 若所有字体文件均不存在

依赖系统字体
  ├── Windows：微软雅黑（msyh.ttc）→ 黑体（simhei.ttf）→ 宋体（simsun.ttc）
  ├── macOS：STHeiti Light
  └── Linux：系统安装的 Noto Sans CJK 等
```

## 5. 常见问题

### Q: 不内嵌字体会怎样？

GUI 界面将依赖系统已安装的中文字体：
- **Windows**：默认有微软雅黑，可正常显示
- **macOS**：默认有苹方，可正常显示
- **Linux**：可能缺少中文字体，界面中文显示为方块
- **Docker/alpine**：默认无中文字体，必须内嵌

### Q: 可执行文件会变大多少？

Noto Sans SC 常规字重 TTF 约 5-8 MB。内嵌后 Release 构建约 10-15 MB（含字体）。Source Han Sans SC 可变字体（VF TTF）约 10-12 MB，OTF 格式约 15-20 MB。

### Q: 可以使用其他中文字体吗？

可以。将任意 TTF/OTF 格式的中文字体重命名为 `NotoSansSC` 放入 `assets/` 即可。
建议使用开源字体，避免商业字体许可问题。

## 6. 保底策略

即使没有内嵌字体且系统缺少中文字体，GUI 也不会崩溃。egui 框架会使用系统默认字体回退渲染：
- 英文字符正常显示
- 中文字符显示为方块（□）或空白
- 程序功能完全正常，仅中文标签不可读
