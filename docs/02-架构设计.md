# 02 - 架构设计

## 1. 架构概述

treesize 采用 **DDD（领域驱动设计）四层架构**，确保领域逻辑与基础设施解耦，核心业务不依赖具体技术实现。

```
┌─────────────────────────────────────────────┐
│              接口层（Interface）              │
│         cli/          gui/                   │
│    参数解析、输出格式化    界面渲染、交互      │
├─────────────────────────────────────────────┤
│              应用层（Application）            │
│  ScanService  ReportService  ClassifyService │
│  DuplicateService                            │
│    编排领域对象，协调业务流程                  │
├─────────────────────────────────────────────┤
│              领域层（Domain）                 │
│  FileNode  ScanEngine  ByteSize  FileCategory│
│  DomainError  ScanOptions  ScanProgress      │
│    核心业务实体与规则，无外部依赖              │
├─────────────────────────────────────────────┤
│           基础设施层（Infrastructure）        │
│  FsScanEngine  Logging  MemoryMonitor        │
│    文件系统访问、日志实现、内存监控             │
└─────────────────────────────────────────────┘
```

## 3. 领域层设计

### 3.1 FileNode 实体

```rust
pub struct FileNode {
    pub path: PathBuf,           // 完整路径
    pub name: String,            // 文件/目录名
    pub size: ByteSize,          // 大小（文件=自身，目录=递归合计）
    pub file_type: FileType,     // File | Directory
    pub extension: String,       // 扩展名（小写）
    pub category: FileCategory,  // 文件分类
    pub modified: Option<SystemTime>,  // 修改时间
    pub children: Vec<FileNode>, // 子节点（仅目录有）
    pub file_count: u64,         // 递归文件数
    pub dir_count: u64,          // 递归目录数
}
```

核心方法：
- `new_file()` / `new_dir()` — 工厂方法
- `aggregate()` — 递归聚合子节点大小和计数
- `sort_by_size_desc()` — 按大小降序排序
- `iter_all()` — 深度优先遍历所有节点
- `count_files()` — 统计文件叶节点数

### 3.2 ScanEngine 抽象

```rust
pub trait ScanEngine: Send + Sync {
    fn scan(
        &self,
        root: PathBuf,
        options: &ScanOptions,
        progress: Option<&(dyn Fn(&ScanProgress) + Send + Sync)>,
        cancel: Option<&CancelToken>,
    ) -> Result<FileNode>;
}
```

通过 trait 抽象扫描引擎，使应用层不依赖具体文件系统实现，便于测试和扩展。

### 3.3 值对象

| 值对象 | 用途 |
|--------|------|
| `ByteSize(u64)` | 字节大小，支持人类可读格式化（KB/MB/GB/TB） |
| `FileCategory` | 文件分类枚举（9 大类 + Other） |
| `FileType` | 文件类型枚举（File / Directory） |
| `ScanOptions` | 扫描选项（排除目录/扩展名、深度、隐藏文件等） |
| `ScanProgress` | 扫描进度（文件数、目录数、已扫描大小、当前路径） |
| `ScanStats` | 扫描统计（总文件数、总大小、耗时、错误数） |
| `CancelToken` | 取消令牌（基于 Arc<AtomicBool>） |

### 3.4 统一错误处理

```rust
#[derive(Debug, thiserror::Error)]
pub enum DomainError {
    #[error("路径不存在：{0}")]
    PathNotFound(String),
    #[error("路径不可访问：{0}")]
    PathInaccessible(String),
    #[error("路径不是目录：{0}")]
    NotADirectory(String),
    #[error("扫描失败：{0}")]
    ScanFailed(String),
    #[error("IO 错误：{0}")]
    Io(#[from] std::io::Error),
    #[error("JSON 序列化错误：{0}")]
    Json(#[from] serde_json::Error),
    #[error("CSV 错误：{0}")]
    Csv(#[from] csv::Error),
    #[error("参数错误：{0}")]
    InvalidArgument(String),
    #[error("内存使用超过限制（{0} MB）")]
    MemoryLimitExceeded(u64),
    #[error("扫描时间超过限制（{0} 秒）")]
    TimeLimitExceeded(u64),
    #[error("文件数超过限制（{0} 个）")]
    FileLimitExceeded(u64),
    #[error("用户取消扫描")]
    ScanCancelled,
}
```

所有错误信息统一中文，禁止泄露敏感信息。

## 4. 应用层设计

### 4.1 ScanService

编排扫描流程：
1. 调用 `ScanEngine::scan()` 执行扫描（实现方负责聚合和排序）
2. 统计扫描结果（总文件数、总目录数、总大小、错误数、耗时）
3. 返回 `(FileNode, ScanStats)`

> 注：`FileNode::aggregate()` 和 `FileNode::sort_by_size_desc()` 由 `ScanEngine` 实现方在 `scan()` 内部调用，`ScanService` 仅负责统计算法和耗时。

### 4.2 ReportService

生成多种格式报表：
- `render_tree()` — 树形文本，支持深度和占比阈值
- `to_json_string()` / `write_json()` — JSON 序列化
- `write_csv()` — CSV 写入
- `top_n_files_report()` / `top_n_dirs_report()` — TopN 排序

### 4.3 ClassifyService

文件分类统计：
- 输入：`FileNode` 树
- 输出：`ClassifyReport`（按大类统计 + 按扩展名统计）
- 分类规则：`FileCategory::from_extension()` 根据扩展名映射

### 4.4 DuplicateService

重复文件扫描：
1. 遍历所有文件叶节点
2. 按文件大小分组（跳过小于阈值的文件）
3. 对同大小文件计算 BLAKE3 哈希
4. 按哈希值分组，生成 `DuplicateReport`

## 5. 基础设施层设计

### 5.1 FsScanEngine（文件系统遍历）

实现 `ScanEngine` trait，跨平台通用扫描器：

```
scan_directory(path, options, depth, progress, cancel, stats)
├── 检查取消令牌和资源限制
├── 读取目录条目（jwalk 并行遍历）
├── 过滤条目（排除目录/扩展名/隐藏文件）
├── 并行处理子节点（jwalk 内部使用 rayon）
│   ├── 文件 → FileNode::new_file()
│   └── 目录 → 递归 scan_directory()
├── 聚合子节点 → FileNode::aggregate()
├── 按大小排序 → FileNode::sort_by_size_desc()
└── 发送进度回调（每 5000 文件一次）
```

并行策略：
- 使用 `jwalk` 并行目录遍历，内部基于 rayon 线程池
- 线程安全计数器（`AtomicU64`）记录扫描进度
- 进度回调满足 `Send + Sync`
- 资源限制检查：文件数上限、时间上限、内存使用上限
- 进度更新节流：每处理 5000 个文件更新一次进度，减少锁竞争

### 5.2 MftScanEngine（NTFS MFT 直接读取）

**Windows 专用**，类似 WizTree 的极速扫描方案：

```
scan(path, options, progress, cancel)
├── 打开卷设备（\\?\C:\）
├── FSCTL_GET_NTFS_VOLUME_DATA 获取卷信息
│   ├── MFT 起始 LCN、记录大小、簇大小等
│   └── 偏移量：MftStartLcn=64, BytesPerFileRecordSegment=40
├── 计算 MFT 字节偏移 = MFT_LCN × bytes_per_cluster
├── ReadFile 读取 MFT 原始数据
├── 解析 MFT 记录
│   ├── 跳过系统文件记录
│   ├── 解析文件名属性（$FILE_NAME）
│   ├── 解析大小属性（$DATA）
│   └── 构建 FileNode 树
└── 返回扫描结果
```

性能优势：
- 直接读取文件系统元数据，无需逐个文件访问
- 速度比 FsScanEngine 快 5-10 倍
- 适用于大目录扫描（100GB+）

### 5.3 UsnScanEngine（USN Journal 增量扫描）

**Windows 专用**，利用 USN Journal 实现增量扫描：

- 记录文件变更日志（创建、修改、删除、重命名）
- 快速检测自上次扫描以来的变化
- 适用于定期监控场景

### 5.4 自动引擎选择与降级

```
ScanOptions::default()
├── Windows → ScanEngineType::Mft（默认）
└── 其他平台 → ScanEngineType::Fs

扫描执行流程：
1. 使用当前引擎扫描
2. 若 MFT 扫描失败（权限不足、非 NTFS 卷等）
3. 自动降级到 Fs 引擎重试
4. 日志记录降级事件
```

### 5.5 日志系统

```
tracing-subscriber
├── 分层输出
│   ├── 文件层：按日期轮转，保留 32 天
│   └── 终端层：stderr 输出
├── 格式：[YYYY-MM-DD HH:MM:SS.SSS] [级别] [线程ID] [模块:行号] - 消息
├── 级别：DEBUG / INFO / ERROR
└── 文件命名：treesize-YYYYMMDD.log
```

## 6. 接口层设计

### 6.1 CLI 接口

```
main.rs
├── 解析 CliArgs（clap）
├── 初始化日志系统
├── 分发模式
│   ├── Cli → cli::run()
│   │   ├── ScanService.scan() 执行扫描
│   │   ├── 输出扫描摘要（stderr）
│   │   └── output::emit_reports() 输出报表
│   └── Gui → gui::run()
│       └── eframe::run_native() 启动 GUI
```

输出规范：
- **stdout**：仅输出主报表（tree/json/csv），支持管道
- **stderr**：扫描摘要、TopN、分类统计、重复文件、日志

### 6.2 GUI 接口

```
TreeSizeApp（eframe::App 实现）
├── 顶部工具栏
│   ├── 路径输入框 + 扫描按钮 + 取消按钮
│   ├── 显示隐藏文件开关
│   └── TopN 数量调节
├── 选项卡面板
│   ├── Tree：可折叠目录树
│   ├── Treemap：Squarified Treemap 可视化
│   ├── TopFiles：TopN 大文件/大目录表格
│   ├── Classify：分类统计表格
│   └── Duplicates：重复文件分组
└── 底部状态栏
    ├── 扫描进度
    └── 扫描统计（文件数、大小、耗时）
```

扫描线程模型：
```
主线程（UI） ←→ Arc<Mutex<ScanState>> ←→ 扫描线程
                  │
                  ├── node: Option<FileNode>
                  ├── stats: Option<ScanStats>
                  ├── progress: ScanProgress
                  ├── running: bool
                  ├── error: Option<String>
                  └── cancel: CancelToken
```

### 6.3 Treemap 可视化

算法：Squarified Treemap

```
squarify(children, rect)
├── 按面积降序排列子节点
├── 贪心选择行：使宽高比最优
│   ├── worst() 计算最差宽高比
│   └── 逐步添加元素直到宽高比恶化
├── place_row() 放置行到矩形短边
└── 递归处理剩余元素和剩余矩形
```

颜色方案：按 `FileCategory` 映射颜色，同类文件色调一致。

### 6.4 Icicle / Flame Graph 可视化

布局算法：递归水平分割

```
compute_layout_v2(root, config)
├── 创建根节点块（宽度 = config.width）
├── 递归 split_children(parent, level)
│   ├── 深度 > max_depth 或宽度 < min_block_width → 停止
│   ├── 非叶子节点：跳过自身宽度，子节点按大小比例横向分割
│   └── 叶子节点：填充剩余宽度
├── 可选自底向上（Flame Graph）：children_sorted 按递归深度排序
└── 返回 Vec<IcicleBlock>
```

方向模式：

| 模式 | 方向 | 用途 | 根节点位置 |
|------|------|------|-----------|
| TopDown | 自顶向下 | Icicle 图 | 顶部第一行 |
| BottomUp | 自底向上 | Flame Graph | 底部第一行 |

SVG 渲染：

- 每个 `IcicleBlock` 渲染为一个 `<rect>` 矩形
- 颜色：优先使用 `FileCategory` 类别色，备选 `depth_color()` 灰阶
- 悬停提示：`<title>` 元素显示路径和大小
- 文本标签：居中显示，宽度不足 40px 时自动隐藏
- 输出：`render_svg()` 返回 SVG 字符串，`render_html_page()` 返回完整 HTML 包裹

输出格式：
- CLI：`--output icicle` / `--output flamegraph` 生成独立 SVG 文件
- `--output all` 同时包含两个 SVG 文件

## 7. 字体方案

| 方案 | 条件 | 说明 |
|------|------|------|
| 内嵌 Noto Sans SC | `assets/NotoSansSC.ttf` 存在 | 编译时通过 `include_bytes!` 内嵌，SIL 开源协议无版权风险 |
| 系统字体回退 | 字体文件不存在 | 运行时加载 Windows/Linux/macOS 系统中文字体 |

构建脚本 `build.rs` 检测字体文件是否存在，设置 `embedded_font` 编译标志。
